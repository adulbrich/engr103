This ladder lists, week by week, the Python and Rust constructs the course has introduced by that point. It grows cumulatively: a construct introduced in an earlier week stays introduced in every later week.

For you as a student, the ladder is a **recommendation, not a rule**. It is the set of tools you are guaranteed to have seen, so it is a safe vocabulary to reach for when you are not sure what you are allowed to use. But if you already know a feature that appears further along, or one the course never covers, you are free to use it: nothing here forbids you from writing code you understand. Recitations and exams assess your understanding, not your restraint.

What the ladder does guarantee runs the other way. **Every graded assessment is solvable using only the constructs listed for its week.** An assignment, recitation, or exam will never require a feature you have not been taught yet, so a student who has followed the course can always solve it with the tools already in hand. The right-hand column below names what has not been introduced yet, so you can see at a glance what a given week's work will never depend on.

## When the two languages print the same value differently

Most values print identically in Python and Rust, but three do not, and they
account for nearly every surprise when an assignment is graded by comparing
printed output. Keep this list somewhere you can find it.

| Value | Python prints | Rust prints |
|---|---|---|
| A boolean | `True` / `False` | `true` / `false` |
| A float that happens to be whole, such as 3285 | `3285.0` | `3285` |
| A list or vector of strings | `['a', 'b']` | `["a", "b"]` |

A float with a real fractional part, such as `1129.21875`, prints the same
characters in both, because Python's `float` and Rust's `f64` are the same
64-bit format and both show the shortest digits that identify the stored value.
Whole numbers, and the text inside a plain `print`, are identical too.

This matters in exactly one place: an assignment graded by comparing what your
program printed, line for line, against one expected output shared by both
languages. Such an assignment is written so that none of the three rows above
can arise, which is why you will see its readings land on real fractions and its
flags reported as `1` and `0` rather than as booleans. From the functions week
onward the grader reads what you `return` instead, and the question stops
arising at all.

## Not used in this course

The course never teaches these constructs, so no lecture, activity, or assessment relies on them, and no graded problem will ever require one. You are still free to use any you already know; they simply are not part of what the course expects.

- **Python:** comprehensions, lambdas, and f-string format specs beyond the basics.
- **Rust:** writing your own generic code (defining type parameters, traits, lifetimes), and designing your own borrowed signatures before week 9.

Two Rust spellings are worth calling out, because they look like exceptions and are not. `parse::<i32>()` is taught in week 5, and `&mut text` appears from week 5 inside the input recipe, `&v` from week 8 in `for x in &v`. In every one of those places the spelling is **given to you and used as written**: you are not defining a type parameter and you are not designing a borrow. What week 9 adds is the understanding of *why* those `&` marks are there, and the first time you choose one yourself.
