This page maps the course subset onto MATLAB, for students heading into MATLAB-based major courses. It covers only the constructs on the [language ladder](/reference/language-ladder), in ladder order, so what you learned here has a direct MATLAB form. The middle column shows the Python form of each construct; the Rust form maps the same way. Cells hold short fragments, not full programs. Read `## What will surprise you` at the end: MATLAB's model differs from the course subset in a few habits worth naming.

## What will surprise you

- **It is 1-indexed.** The first element is `xs(1)`, not `xs(0)`, and the last is `xs(end)`. Indexing uses parentheses, the same syntax as a function call, so `xs(1)` and `add(1)` look alike.
- **It is matrix-first.** Every value is a matrix; a plain number is just a 1-by-1 one. `*`, `/`, and `^` mean matrix operations, so to work element by element you write `.*`, `./`, and `.^`. This is the habit the course subset does not have.
- **It is weakly typed.** There are no type annotations. A variable is whatever you last assigned to it, and numbers are double by default, so the `i32` versus `f64` distinction from the course subset disappears.
- **Blocks close with `end`.** Indentation is cosmetic. Every `if`, `while`, `for`, and `function` is terminated by an explicit `end`, not by a change in indentation as in Python or by braces as in Rust.
- **`=` versus `==`.** A single `=` assigns; a double `==` compares. Using `=` where you meant `==` is a syntax error inside a condition, but it is a habit worth watching. Note also that "not equal" is `~=`, not `!=`.
- **Scripts versus functions.** A script file runs top to bottom and shares the workspace; a function file defines reusable functions with their own local scope. A trailing semicolon suppresses the automatic printing of a result, so leave it off only when you want to see the value.
