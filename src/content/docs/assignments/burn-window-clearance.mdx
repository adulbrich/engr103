Six weeks into the cruise to Mars, the crew keeps the habitat's daily safety checks running exactly the way they will once nobody on Earth can talk you through a bad call. The command module has one number that matters most: a single status code that condenses the whole habitat's health into nominal, advisory, critical, or an emergency override when a crew member has taken manual control. HAB, the habitat's assistant, has already offered its own rule for part of that check. Your job as the flight-software crew member is to write the status function the command display depends on, and to catch HAB's mistake before it clears something that is not actually safe.

## The Problem

The crew display in the command module condenses the habitat's health into a single status code: `0` for nominal, `1` for advisory, `2` for critical, and `3` for an emergency override, when a crew member has thrown the manual switch and taken control by hand. The code drives a colored ring on the display that refreshes twice a second. Two live readings feed the decision, the cabin pressure and the cabin oxygen level, but the manual switch outranks both: when it is thrown, the code is `3` no matter what the readings say.

Write `system_status(cabin_pressure_kpa, oxygen_percent, emergency_override)`, returning the status code. What it must return, in this priority order:

1. Return `3` whenever `emergency_override` is `true`, no matter what the two readings say. The override outranks every other check.
2. Otherwise, return `2` when the cabin pressure is below `95.0` kilopascals or the oxygen level is below `18` percent. Either reading on its own breaching its hard floor is critical.
3. Otherwise, return `1` when the two readings are not both comfortably in range. Comfortably in range means the cabin pressure is at least `99.0` kilopascals and the oxygen level is at least `20` percent, both at once. A reading that clears its hard floor but has not reached that comfortable range is an advisory.
4. Otherwise, return `0`.

The function returns a whole-number status code (`0`, `1`, `2`, or `3`). How you arrange the comparisons, which of `and`, `or`, and `not` each outcome needs, and what intermediate values you give names to along the way, is entirely your decision.

**Assumptions and edge cases.** `cabin_pressure_kpa` is a float and `oxygen_percent` is a whole percent; `emergency_override` is a boolean read from the manual switch. The boundaries are exact: `95.0` and `18` are the hard floors, and a reading exactly at a hard floor is not below it, so it is not critical. Comfortably in range needs `99.0` and `20` exactly met, so a habitat sitting exactly on a hard floor is an advisory, not critical and not nominal. A thrown override always returns `3`, even when both readings would otherwise be nominal.

A single reading dipping low on its own is just an advisory, not a critical."

Flight rule: no HAB advice is trusted unverified. Decide whether HAB's rule is right before you build anything on it, and let your test cases settle the question.

## Step 1: Write Your Acceptance Tests

Before writing any code, decide what correct behavior looks like. Write a set of test cases for `system_status` as a plain table of rows: the three inputs (`cabin_pressure_kpa`, `oxygen_percent`, `emergency_override`) and the status code you expect back. Do not use `assert` yet; a table of rows is what this step wants. For each row, work out the expected code by hand from the priority order, paying attention to which readings sit exactly on a hard floor or on the comfortable-range floor.

Your table must include, and label, at least these cases:

- An override case that returns `3` while the readings themselves would be critical, to prove the override really outranks the readings.
- A critical case driven by low pressure.
- A critical case driven by low oxygen.
- An advisory case.
- A nominal case.
- One case that lands exactly on a boundary: a reading exactly at `95.0`, `99.0`, `18`, or `20`.
- At least one more case whose expected code you compute fully by hand.

Think about what HAB claimed while you do this: a good set of tests would catch a rule that treated the critical check the wrong way.

## Paper Practice

Trace this program by hand, on paper. It uses nested function calls and a boolean condition, the patterns from the [Scope and the Call Stack](/lectures/scope-and-the-call-stack/) and [Booleans and Conditionals](/lectures/booleans-and-conditionals/) lectures. Build a variable table: for the call to `is_low_power`, write the value its `battery_percent` parameter holds and what it returns; then, for `check_drill_status`, write the values bound to its two parameters, to `low_power`, and to `result`. Write the exact value the program prints.

```python title="trace_me.py"
def is_low_power(battery_percent):
    return battery_percent < 25

def check_drill_status(oxygen_percent, battery_percent):
    low_power = is_low_power(battery_percent)
    if oxygen_percent >= 20 and not low_power:
        result = 1
    else:
        result = 0
    return result

status = check_drill_status(22, 18)
print(status)
```

<Reveal label="Reveal the completed trace">
The call `check_drill_status(22, 18)` pushes a frame with `oxygen_percent = 22` and `battery_percent = 18`. Inside it, `is_low_power(18)` pushes a second frame with `battery_percent = 18`, computes `18 < 25`, and returns `true`; that frame is popped, and `true` is bound to `low_power` in `check_drill_status`'s own frame.

| Line | frame | `oxygen_percent` | `battery_percent` | `low_power` | `result` |
|---|---|---|---|---|---|
| `is_low_power(18)` called | `is_low_power` | | `18` | | |
| `return battery_percent < 25` | `is_low_power` | | `18` | | (returns `true`) |
| `low_power = is_low_power(battery_percent)` | `check_drill_status` | `22` | `18` | `true` | |
| `if oxygen_percent >= 20 and not low_power:` | `check_drill_status` | `22` | `18` | `true` | |
| `result = 0` | `check_drill_status` | `22` | `18` | `true` | `0` |

The condition checks `22 >= 20`, which is `true`, `and`ed with `not low_power`, which is `not true`, or `false`. `true and false` is `false`, so the `if` block is skipped and the `else` block runs, binding `result` to `0`. The program prints `0`.
</Reveal>

Photograph your trace and include it in your PDF on Canvas. This part is graded on completion (the attached photograph), not on whether every cell is right, so attempt it by hand first, then open the reveal to check yourself.
