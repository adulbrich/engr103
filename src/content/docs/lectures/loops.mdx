Suppose you need to print the numbers 1 through 100, or add up every measurement in a day's readings, or keep asking a question until the answer is the one you need. You could write the same line a hundred times, but that is slow to type, easy to get wrong, and impossible to adjust: change the count to 1000 and you are back at the keyboard for hours. Functions already gave you one kind of reuse, writing a block of steps once and calling it from many places, but a function still runs its body once per call. What you are missing is a way to run one block of steps over and over within a single run of the program, repeating it as many times as the work demands without writing it out more than once. That is what a loop does.

## The idea of a loop

A **loop** is a block of code that runs repeatedly. Instead of the straight line every program has followed so far, where each statement runs once and control moves on, a loop sends control back to the start of its block and runs it again, and again, until some condition tells it to stop. The two loops in this lecture, `while` and `for`, differ only in how they decide when to stop; the repetition itself is the same idea in both.

## The while loop

The most basic loop is the **while loop**. It pairs a condition with a block of code, called the loop body, and it runs the body over and over for as long as the condition stays true. The condition is an ordinary boolean expression, the same kind you wrote for an `if` statement: it reduces to `true` or `false`. The difference from an `if` is what happens after the body runs. An `if` checks its condition once, runs its block at most one time, and moves on. A `while` loop checks its condition, runs its body, and then goes back and checks the condition again, repeating that cycle until the check finally comes out `false`.

The mechanism is worth stating one step at a time, because every loop in this lecture rests on it. When execution reaches a `while` loop, the program evaluates the condition. If it is `false` right away, the body is skipped entirely and the program continues past the loop, exactly as it would skip an `if` whose condition was false. If the condition is `true`, the program runs the body once, top to bottom. Then, instead of moving on, control returns to the condition and evaluates it again. If it is still `true`, the body runs another time; if it is now `false`, the loop ends and the program continues with whatever comes after it. The value the condition depends on is usually a variable the body changes, so that each pass moves the loop one step closer to stopping. That variable is the **loop variable**: the value the condition tests and the body updates on every pass.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="countup.py"
count = 1
while count <= 3:
    print(count)
    count = count + 1
print("done")
```
</TabItem>
<TabItem label="Rust">
```rust title="countup.rs"
fn main() {
    let mut count = 1;
    while count <= 3 {
        println!("{}", count);
        count = count + 1;
    }
    println!("done");
}
```
</TabItem>
</Tabs>

Trace it pass by pass, watching `count`. It starts at `1`. The loop evaluates `count <= 3`: `1 <= 3` is `true`, so the body runs, printing `1`, then setting `count` to `2`. Control returns to the condition: `2 <= 3` is `true`, so the body runs again, printing `2` and setting `count` to `3`. Back to the condition: `3 <= 3` is `true`, so the body prints `3` and sets `count` to `4`. Control returns to the condition one more time, and now `4 <= 3` is `false`. This last check is the one learners skip, and it is the whole point: the loop does not stop because the body decided to, it stops because the condition was re-evaluated and came out false. The body does not run a fourth time; the loop ends, and the program moves on to print `done`.

```text frame="terminal" title="Output"
1
2
3
done
```

<WhatDiffers>
<Fragment slot="differs">
Rust declares the loop variable with `let mut`, not plain `let`, and that is not optional here: the body reassigns `count` on every pass, and Rust forbids reassigning any variable that was not marked mutable with `mut`, as the Variables lecture described. Python has no such rule; a variable is free to be reassigned at any time, so `count = count + 1` just works.
</Fragment>
</WhatDiffers>

Forget the `mut` in Rust and the compiler refuses the program rather than letting a broken loop run.

```rust title="countup_bad.rs, a counter without mut (will not compile)"
fn main() {
    let count = 1;             // missing mut
    while count <= 3 {
        println!("{}", count);
        count = count + 1;     // error: cannot assign twice to immutable variable `count`
    }
}
```

```bash title="Compile the broken version"
rustc countup_bad.rs
```

```text frame="terminal" title="Output"
error[E0384]: cannot assign twice to immutable variable `count`
 --> countup_bad.rs:5:9
```

Because a loop that never changes its loop variable is almost always a mistake, Rust turning a forgotten `mut` into a compile error is the compiler catching a bug before the program ever runs. It is the same checks-before-running difference you have seen throughout the course, now landing on the one line a loop most depends on.

## Termination and infinite loops

A loop is only useful if it eventually stops, and stopping is not automatic. Look again at what ended the count-up loop: the body kept increasing `count` until the condition `count <= 3` became false. The responsibility for reaching that false was entirely in the body. If the body had never changed `count`, the condition `1 <= 3` would have stayed true on every single check, and the loop would have run forever. A loop whose condition never becomes false is an **infinite loop**: it repeats endlessly and never lets the program move past it. Almost every infinite loop is a bug, because almost every program is meant to finish.

The rule that prevents one is simple to state and easy to forget: the body must, on every path through it, make progress toward the condition becoming false. A countdown makes the requirement concrete. The loop below starts at `3` and shrinks its loop variable by one each pass, so the condition `n > 0` is guaranteed to fail after a fixed number of steps.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="countdown.py"
n = 3
while n > 0:
    print(n)
    n = n - 1
print("liftoff")
```
</TabItem>
<TabItem label="Rust">
```rust title="countdown.rs"
fn main() {
    let mut n = 3;
    while n > 0 {
        println!("{}", n);
        n = n - 1;
    }
    println!("liftoff");
}
```
</TabItem>
</Tabs>

With `n` starting at `3`, the condition `3 > 0` is true and the body prints `3` then sets `n` to `2`; `2 > 0` is true, so it prints `2` and sets `n` to `1`; `1 > 0` is true, so it prints `1` and sets `n` to `0`; then `0 > 0` is false, the loop ends, and `liftoff` prints. Each pass moves `n` strictly closer to the boundary, so the loop is guaranteed to stop.

```text frame="terminal" title="Output"
3
2
1
liftoff
```

Now imagine deleting the line `n = n - 1` from either version. The body would print `n` and then do nothing to change it, so `n` would stay `3`, the condition `3 > 0` would be true on every check, and the program would print `3` forever without ever reaching `liftoff`. That is an infinite loop, and it is worth understanding exactly why it happens rather than only how to avoid it: nothing is broken in the language, the loop is doing precisely what it was told, repeating its body while a condition that never changes stays true. The fix is always the same in shape, make the body change the value the condition depends on, in the direction that will eventually make it false.

:::caution[Stopping a runaway loop]
If you ever run a program that is stuck in an infinite loop, printing forever or simply hanging, you can stop it from the terminal by pressing `Ctrl` and `C` together. That sends the running program a signal to quit, handing control back to you so you can find and fix the loop. It is a normal part of writing loops to trip an infinite one occasionally; knowing how to interrupt it means a mistake costs you a keystroke, not a frozen machine.
:::

:::note[The deliberate forever loop]
A `while` loop in both languages checks its condition before the first pass, so a body can run zero times if the condition starts out false. That is sometimes the wrong shape: you may want the body to run once and only then decide whether to go around again, which is what asking a person for input looks like.

Both languages reach that shape the same way, with a loop whose condition is never false and a `break` inside the body to escape. Python writes it `while True:`, and Rust has a dedicated `loop { ... }` keyword for it. The `break` is described later in this lecture. Both forms turn into an accidental infinite loop the moment that escape is unreachable, so write the `break` before you write the body around it.
:::

## Counting with a for loop

A great many loops do the same structural thing: set a counter to a starting value, run the body, step the counter, and stop once it passes a limit. The count-up loop earlier was exactly this pattern, spread across three separate places, the initial `count = 1`, the condition `count <= 3`, and the update `count = count + 1`. Scattering the counting logic like that is easy to get wrong: forget the update and you have an infinite loop, put it in the wrong spot and the count is off. The **for loop** exists for precisely this case. It walks a loop variable through a known sequence of values, one value per pass, and handles the starting point, the stepping, and the stopping for you, so there is no separate counter to initialize or forget to advance.

In Python, the sequence comes from `range`. Writing `range(5)` produces the whole numbers starting at `0` and stopping *before* `5`, that is `0, 1, 2, 3, 4`, five values in all. The `for` loop takes its loop variable through those values in order: on the first pass the variable is `0`, on the next `1`, and so on, and after the pass where it is `4` there are no values left, so the loop ends. In Rust, the sequence is written directly as a range, `0..5`, which means the same thing: the numbers from `0` up to but not including `5`.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="repeat.py"
for i in range(5):
    print(i)
```
</TabItem>
<TabItem label="Rust">
```rust title="repeat.rs"
fn main() {
    for i in 0..5 {
        println!("{}", i);
    }
}
```
</TabItem>
</Tabs>

Trace the values the loop variable `i` takes. It begins at `0`, so the body prints `0`. The loop moves `i` to the next value in the sequence, `1`, and prints it. Then `2`, then `3`, then `4`, each printed as the body runs. After printing `4`, the loop asks the sequence for the next value, but `5` is excluded, so there is none: the loop ends. The body ran exactly five times, once for each value in `range(5)` or `0..5`, and at no point did you write an update or a stopping condition by hand.

```text frame="terminal" title="Output"
0
1
2
3
4
```

The detail that trips up nearly every beginner is that the top of the range is excluded, not included. A range like this is called **half-open**: it includes its starting value but stops just short of its ending value. This is why `range(5)` and `0..5` both give five values ending at `4`, not at `5`. The payoff is that the count is right there in the range: `range(5)` runs the body five times, `range(100)` runs it a hundred. A range also does not have to start at `0`; `range(1, 4)` in Python and `1..4` in Rust both give `1, 2, 3`, starting where you say and still stopping one short of the end. When you truly want the ending value included, Rust offers a second form written with an equals sign, `0..=5`, which runs from `0` through `5` and does include the `5`, six values in all. Python has no `=` spelling; to include an endpoint you raise the stop value yourself, writing `range(0, 6)` to cover `0` through `5`.

<WhatDiffers>
<Fragment slot="differs">
Python draws the sequence from the `range` function: `range(5)` gives `0` through `4`, and `range(1, 4)` gives `1` through `3`. Rust writes the sequence as a range literal instead: `0..5` and `1..4` mean the same half-open spans. Both languages exclude the top value by default, so `range(5)` and `0..5` each run the body five times. Only Rust has an inclusive form, `0..=5`, that keeps the top value; Python has no `..=` and instead raises the stop number, as in `range(0, 6)`, to cover the same span.
</Fragment>
</WhatDiffers>

:::note[Why counting from zero is the default]
It can feel unnatural to count from `0` to `4` when you mean five things, but the half-open range from zero is a deliberate convention, not an accident. It makes the size of the range obvious at a glance, since `range(n)` and `0..n` always produce exactly `n` values, and it makes two ranges join cleanly, since `0..5` followed by `5..10` covers `0` through `9` with no value repeated and none skipped at the seam. When you reach strings and lists in a later lecture, you will find their positions are numbered from `0` as well, and a `for` loop over `range(n)` or `0..n` will line up with those positions exactly. Learning to think in half-open ranges now pays off directly then.
:::

## break

A `for` or `while` loop normally runs until its sequence is exhausted or its condition turns false. Sometimes you need to leave earlier, the instant something inside the body tells you to, before the loop would end on its own. The **break** statement does exactly that: when it runs, the loop stops immediately, skipping any remaining passes, and the program continues with whatever comes after the loop. A `break` almost always sits inside an `if`, so that it fires only when a particular case occurs rather than on every pass.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="findfirst.py"
for i in range(10):
    if i == 3:
        print("stopping")
        break
    print(i)
```
</TabItem>
<TabItem label="Rust">
```rust title="findfirst.rs"
fn main() {
    for i in 0..10 {
        if i == 3 {
            println!("stopping");
            break;
        }
        println!("{}", i);
    }
}
```
</TabItem>
</Tabs>

The range here runs from `0` to `9`, so without the `break` the body would run ten times. Trace what actually happens. On the first pass `i` is `0`; the `if` condition `i == 3` is false, so the `break` is skipped and the body prints `0`. The same happens for `i` at `1` and `2`, printing each. On the pass where `i` is `3`, the `if` condition is now true, so the body prints `stopping` and then runs `break`. The loop stops at once: the `print(i)` on the last line never runs for `3`, and the loop never advances to `4` through `9`. Execution jumps straight to after the loop, which here is the end of the program.

```text frame="terminal" title="Output"
0
1
2
stopping
```

The loop was set up to run ten times but ran its body only four, because `break` overrode the range. That is the whole value of it: a loop can describe the most passes you might need, and `break` cuts the repetition short the moment the work is actually done.

## continue

Where `break` abandons the whole loop, **continue** abandons only the current pass. When `continue` runs, the rest of the body is skipped for this one pass, but the loop itself does not end: control jumps straight to the next value or the next condition check, and the loop carries on. It is the tool for "skip this one and keep going," as opposed to `break`'s "stop altogether."

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="skip.py"
for i in range(5):
    if i == 2:
        continue
    print(i)
```
</TabItem>
<TabItem label="Rust">
```rust title="skip.rs"
fn main() {
    for i in 0..5 {
        if i == 2 {
            continue;
        }
        println!("{}", i);
    }
}
```
</TabItem>
</Tabs>

The loop steps `i` through `0, 1, 2, 3, 4`, the full half-open range, and the `continue` changes only one of those passes. When `i` is `0` the `if` is false, so `continue` is skipped and the body prints `0`; the same for `1`. When `i` is `2` the `if` is true, so `continue` runs: the rest of the body, the `print`, is skipped for this pass only, and the loop moves on to the next value. When `i` is `3` and then `4` the `if` is false again, so both print. The result is every value except `2`. Notice that the loop did not stop at `2` the way `break` would have; it skipped just that pass and kept running, which is the entire difference between the two.

```text frame="terminal" title="Output"
0
1
3
4
```

## Nested loops

A loop body is just a block of code, and a loop is a statement, so nothing stops you from putting one loop inside another. This is a **nested loop**: an outer loop whose body contains an inner loop. The mechanism follows directly from what a loop already does, with no new rule. Each pass of the outer loop runs its body once, and if that body is an inner loop, then running it once means running the inner loop all the way through, start to finish, before the outer loop can move to its next pass. The inner loop restarts from the beginning every single time the outer loop comes around again.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="grid.py"
for i in range(1, 4):
    for j in range(1, 4):
        print(i * j)
```
</TabItem>
<TabItem label="Rust">
```rust title="grid.rs"
fn main() {
    for i in 1..4 {
        for j in 1..4 {
            println!("{}", i * j);
        }
    }
}
```
</TabItem>
</Tabs>

The outer loop walks `i` through `1, 2, 3`, and for each of those the inner loop walks `j` through `1, 2, 3`. Trace it carefully. The outer loop sets `i` to `1` and runs its body, which is the entire inner loop: `j` becomes `1` and prints `1 * 1`, which is `1`, then `j` becomes `2` and prints `1 * 2`, which is `2`, then `j` becomes `3` and prints `3`. The inner loop is now finished, so the outer loop moves on and sets `i` to `2`, and the inner loop starts over from `j` equal to `1`, printing `2`, then `4`, then `6`. The outer loop sets `i` to `3` one last time, and the inner loop runs once more, printing `3`, then `6`, then `9`.

```text frame="terminal" title="Output"
1
2
3
2
4
6
3
6
9
```

Count the passes and the important property of nesting appears. The outer loop runs three times, and each of those runs the inner loop three times, so the inner body runs <Latex formula="3 \times 3 = 9" /> times in total, which is exactly the nine numbers printed. The counts multiply, they do not add: an outer loop of `n` passes wrapped around an inner loop of `m` passes runs the innermost body <Latex formula="n \times m" /> times. This is why nested loops are powerful for grid-shaped or table-shaped work, where every value of one thing has to be paired with every value of another, and also why they demand care, since a modest-looking pair of loops over a few hundred values each quietly runs its inner body tens of thousands of times.

## Takeaways

A loop runs a block of code repeatedly, sending control back to the start of the block instead of moving on after a single pass. One written-out body can then do work that would otherwise take endless retyping.

The `while` loop is the mechanism in its plainest form: it evaluates a condition, runs its body if the condition is true, then returns to evaluate the condition again, repeating until a check finally comes out false. That final false check is what ends the loop, so the body carries the responsibility of changing the loop variable the condition depends on. A body that never makes progress leaves the condition forever true and produces an infinite loop, the classic loop bug, which you interrupt with `Ctrl` and `C` and fix by making the body move toward the condition's boundary.

The `for` loop packages the most common counting pattern, walking a loop variable through a known sequence: `range(n)` in Python and `0..n` in Rust. Both are half-open, so they run exactly `n` times and stop one short of the top. Rust adds an inclusive `0..=n` form that keeps the endpoint, while Python raises the stop value instead.

Inside any loop, `break` stops the whole loop immediately and `continue` skips only the current pass and moves to the next, giving you finer control than the condition or range alone. Nesting one loop inside another runs the inner loop in full for every pass of the outer, so the pass counts multiply.

With these constructs in hand, the next lecture turns from the machinery of loops to the handful of reusable patterns, accumulating a total, counting matches, searching for a value, that the same few loop shapes are used to build over and over.
