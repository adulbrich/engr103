WRO's field office put solar panels on its south-facing roof several years ago, 240 individual panels in all, and the budget office now wants one number before it signs off on next year's energy plan: the total energy the array will generate over its whole working life. The array keeps producing power for years, giving up a little output each year, until the array's output sinks below the level the manufacturer's warranty still stands behind. Your job as a junior engineer on the office's software team is to write the function that adds up the array's lifetime output, year by year, and to judge AURA's shortcut before you build anything on it.

## The Problem

The array's data sheet gives a steeper degradation curve than most rooftop solar. Across the industry, the median crystalline-silicon panel loses only about 0.5 percent of its output per year (NREL, Jordan and Kurtz, *Compendium of Photovoltaic Degradation Rates*, 2016), but the office bought an older discount panel line for this roof, and its output falls off noticeably faster than that.

The array's output in its first year of operation is a known starting value. Every year after that, the output falls by a fixed percentage of the year before it, so a smaller number is what shrinks the year after that, and the shrinking compounds. The array keeps counting toward the office's budget only for as long as its output stays at or above the level the manufacturer's warranty still covers; the moment a year's projected output would fall below that floor, the array's useful life for budgeting purposes is over, and that year's output is left out.

Write `lifetime_generation_kwh(start_output_kwh, degradation_percent, floor_kwh)`, returning the total energy the array generates over its life, in kilowatt-hours, as a float. There is no exponentiation operator on the language ladder, and the number of years that qualify depends on all three inputs, not on a fixed count, so you cannot raise a single factor to a fixed power and you cannot write the growth out by hand for a general case.

The function returns a float. How you track the array's output year to year, and what intermediate values you give names to along the way, is entirely your decision.

**Assumptions and edge cases.** `start_output_kwh` is a float, greater than `0.0`. `degradation_percent` is a float, strictly greater than `0.0` and strictly less than `100.0`: the array always gives up a little output each year, never none and never all of it at once. `floor_kwh` is a float, greater than `0.0`, and it can sit below, exactly at, or above `start_output_kwh`. Handle a `floor_kwh` above `start_output_kwh`, where the very first year already fails to clear the floor and nothing is added to the total, and a `floor_kwh` exactly equal to `start_output_kwh`, where the first year clears it but the second does not.

<Aside type="danger" title="AURA has a shortcut for the lifetime total. Decide whether to trust it.">

The array gives up only a little each year, so the years are near enough to each other that the first year stands in for all of them, and tracking every single year's own value is bookkeeping you do not need."

## Paper Practice

Trace this program by hand, on paper. It uses the running-product accumulator from the [Loop Patterns](/lectures/loop-patterns/) lecture. Build a variable table with a row for each pass of the `while` loop, tracking `n` at the start of the pass and `value` after it. Write the exact value the program prints.

```python title="trace_me.py"
value = 512.0
factor = 0.75
n = 1
while n <= 3:
    value = value * factor
    n = n + 1
print(value)
```

<Reveal label="Reveal the completed trace">
Each pass multiplies `value` by the fixed `factor`, and then advances `n`.

| Pass | `n` at start of pass | `value` after |
|---|---|---|
| 1 | `1` | `384.0` |
| 2 | `2` | `288.0` |
| 3 | `3` | `216.0` |

After the third pass, `n` becomes `4`, and the condition `n <= 3` is false, so the loop ends. The program prints `216.0`. The same program written in Rust prints its whole-valued `f64` without the trailing zero, `216`.
</Reveal>
