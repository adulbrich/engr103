ENGR 103 teaches you to turn an engineering problem into a program that solves it. You will write code in two languages, Python and Rust, from the first week to the last. No prior programming experience is assumed.

## Why Two Languages

Learning one language teaches you that language. Learning two at once teaches you what is the idea and what is the spelling.

Python runs your code immediately and lets you try things fast. Rust checks your code before it runs and refuses to build a program whose types do not line up or whose memory use is unsound. Every concept in this course appears in both, side by side, so you see the same idea in a permissive language and in a strict one. The differences are where the learning is: when Rust rejects a line Python accepts, the compiler is telling you something true about the code that Python let you get away with.

You may answer in either language on graded work, and a correct answer in either earns full marks.

## How the Course Fits Together

Five kinds of work, each with a different job:

- **Lecture notes** explain the concepts. You read them before class, so class time is spent working rather than listening.
- **Activities** are the guided problem sets you work in the lecture room. You predict, trace, and fix code, then check your answer against the resolution on the page.
- **Assignments** are the take-home practice: one substantial problem a week that you write, test, and submit. You may use any tool on them, including AI.
- **Recitations** are in-class sessions where you work the same kind of problem on your own, on paper, with no tools. This is where you show the practice transferred.
- **Exams**, a midterm and a final, are multiple choice on paper.

The pattern is deliberate. Assignments are the training set and recitations are the test set: each assignment prepares the recitation that follows it, with the same problem skeletons in a different costume. Most of your grade is earned in the room, which is why the take-home work can stay low stakes and open to any tool. If you do the practice yourself, nothing in the room is a surprise. Canvas carries the exact weights and dates.

The [Schedule](/overview/schedule/) shows which lecture, assignment, and recitation belong to each week.

## What You Need Before You Start

- Comfort using a computer and a file system.
- Basic algebra.
- A willingness to read error messages instead of fearing them. An error is a message from a tool that has found a real problem, not a verdict on you.

## How to Do Well

**Read the notes before class.** The session assumes it. A student who arrives having read gets an hour of practice; a student who has not gets an hour of catching up.

**Start assignments early.** Debugging takes the time it takes, and it does not compress into the last evening.

**Do the assignment yourself even when a tool could do it for you.** The recitation asks the same kind of question with the tools gone. Practice you outsourced is practice you did not get.

**Ask.** Office hours, the recitation TAs, and your peers are all faster than being stuck.
