## Problem Set

### Problem 1: The Instrument Readings

**Context.** Three readings go on the console: how many seconds are in a three-minute hold, how much fuel remains after a burn, and a status word the panel stores in binary.

**Requirements.**

1. Replace the first `0` with the number of seconds in three minutes (three times sixty seconds).
2. Replace the second `0` with the fuel remaining when a `350` kilogram burn is taken from a `1500` kilogram load.
3. Replace the third `0` with the binary literal `0b101010`, and let the program print its value. A binary literal is written directly in the code, and printing it shows the whole number it represents, as in the [Data Representation](/lectures/data-representation/) lecture.

The modeling step is deciding what each reading means as a number; the analysis step is writing the arithmetic and the literal that produce it.

**The program.**

```python title="readings.py (provided)"
print(0)   # seconds in a three-minute hold
print(0)   # fuel remaining: a 350 kg burn from a 1500 kg load
print(0)   # the status word stored as the binary literal 0b101010
```
</TabItem>

**Assumptions and edge cases.** Every reading is a whole number. Write each one as an expression that computes the value, not as the final number typed directly; the point is that the program does the arithmetic.

### Problem 2: The Sensor Total, and One of HAB's Suggestions

**Context.** One panel reading combines a baseline of `2` units with three banks of `4` sensors each, for a total of `14`. HAB has written a version of this reading.

**Requirements.**

1. Replace the `0` with an expression for the total: the baseline `2` plus three banks of `4` sensors, which is `2` plus the product of `3` and `4`. The result is `14`.

The modeling step is reading the sentence as "a baseline plus a product"; the analysis step is writing the expression so precedence adds the baseline to the product, not to a grouped sum.

**The program.**

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="sensors.py (provided)"
# TODO: replace the 0 with the sensor total described.
print(0)   # baseline 2 plus three banks of 4 sensors
```
</TabItem>
<TabItem label="Rust">
```rust title="sensors.rs (provided)"
fn main() {
    // TODO: replace the 0 with the sensor total described.
    println!("{}", 0);   // baseline 2 plus three banks of 4 sensors
}
```
</TabItem>
</Tabs>

**Expected output.**

```text frame="terminal" title="Output"
14
```

<Aside type="danger" title="HAB suggested this expression. Check it before you use it.">
HAB offered `(2 + 3) * 4` for the sensor total. Work out what it prints before you trust it.

HAB's version prints `20`, not `14`. The parentheses force the addition first, so it computes five banks of four rather than a baseline plus three banks. Without parentheses, multiplication runs before addition, so `2 + 3 * 4` computes the three banks of four first, then adds the baseline of two, giving `14`. Write it so the product happens before the baseline is added.
</Aside>

**Assumptions and edge cases.** All values are whole numbers.

## Paper Practice

Reduce this expression by hand, on paper, one operator at a time, and write the single value it comes out to. Photograph your steps and attach them. This part is graded on completion, not correctness, so reduce it yourself first, then open the reveal to check.

```text title="Reduce this expression"
20 - 3 * 4
```

<Reveal label="Reveal the reduction">
```text title="Reducing 20 - 3 * 4"
20 - 3 * 4
20 - 12      (multiplication runs before subtraction: 3 * 4 is 12)
8            (20 - 12)
```

Multiplication has higher precedence than subtraction, so `3 * 4` reduces first to `12`, and only then does `20 - 12` give `8`.
</Reveal>
