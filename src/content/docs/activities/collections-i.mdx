This activity puts into practice the [Collections I: Lists and Vectors](/lectures/collections-i/) lecture. You will predict what a list holds after several pushes and an overwrite and which of its elements is largest, compare how Python and Rust reach the last element while walking the sequence, and choose the one loop line that completes a program reading each element and its neighbor. By the end, you will be able to trace a growing sequence by hand and read the exact error a bad index produces in each language.

## Warm-up

A quick refresher before the sections. A list, called a vector in Rust, is an ordered run of values you create as a literal, reach into by position starting from zero, and measure with a length. Here are those three pieces, in both languages.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="warmup.py"
nums = [10, 20, 30]
print(nums)
print(nums[0])
print(len(nums))
```
</TabItem>
<TabItem label="Rust">
```rust title="warmup.rs"
fn main() {
    let nums = vec![10, 20, 30];
    println!("{:?}", nums);
    println!("{}", nums[0]);
    println!("{}", nums.len());
}
```
</TabItem>
</Tabs>

```bash title="Run the Python program"
python3 warmup.py
```

```text frame="terminal" title="Output"
[10, 20, 30]
10
3
```

Rust prints the same three lines, using `{:?}` to show the whole vector and `nums.len()` as a method after the dot rather than the `len(nums)` function. With those pieces fresh, the sections below grow, walk, and break a sequence.

## Predict the List and the Largest Element

The program below pushes, overwrites, and reads back elements, then hunts for the largest one, and the final list is easy to get wrong. You commit to an answer first, then run the program to check it.

Read both programs below and write down, on paper or in a comment, three things: the length the program prints, the exact final list, and the largest element its loop finds. Do not run them yet. Trace the list one line at a time, starting from the literal and applying each change in turn. Then scan the final list for its largest value. Predict for both languages, and notice whether your two answers agree.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="predict.py"
nums = [4, 9, 6]
nums.append(9)
nums[1] = 2
nums.append(nums[1] + 3)
print(len(nums))
largest = nums[0]
for i in range(len(nums)):
    if nums[i] > largest:
        largest = nums[i]
print(nums)
print(largest)
```
</TabItem>
<TabItem label="Rust">
```rust title="predict.rs"
fn main() {
    let mut nums = vec![4, 9, 6];
    nums.push(9);
    nums[1] = 2;
    nums.push(nums[1] + 3);
    println!("{}", nums.len());
    let mut largest = nums[0];
    for i in 0..nums.len() {
        if nums[i] > largest {
            largest = nums[i];
        }
    }
    println!("{:?}", nums);
    println!("{}", largest);
}
```
</TabItem>
</Tabs>

<Reveal label="Reveal the real output and reconcile it with your prediction">
```bash title="Run the Python program"
python3 predict.py
```

```text frame="terminal" title="Output"
5
[4, 2, 6, 9, 5]
9
```

```bash title="Compile and run the Rust program"
rustc predict.rs
./predict
```

```text frame="terminal" title="Output"
5
[4, 2, 6, 9, 5]
9
```

The list starts as `[4, 9, 6]`. The first push appends `9`, making `[4, 9, 6, 9]`. Then `nums[1] = 2` overwrites the element at position 1, the original `9`, with `2`, leaving `[4, 2, 6, 9]`. The third push is the trap: it appends `nums[1] + 3`, and `nums[1]` is now `2`, not the `9` it started as, so it appends `2 + 3`, which is `5`, giving `[4, 2, 6, 9, 5]`. The length is `5`.

The largest loop starts `largest` at `nums[0]`, which is `4`, then walks the final list: `4` is not greater than `4`, `2` is not, `6` is greater so `largest` becomes `6`, `9` is greater so `largest` becomes `9`, and `5` is not. The largest element is `9`. If you predicted `12` for the last pushed value, you used the original `nums[1]` of `9` instead of the `2` that overwrote it; if you predicted a largest of `6`, you likely forgot the `9` that the first push left near the end of the list.

Both languages print the identical three lines. Append, index assignment, reading an element by index, and a loop that keeps a running best all behave the same in each. The only difference is that Rust requires `let mut` on a vector you change, writes the push as `nums.push(9)`, and walks the positions with `for i in 0..nums.len()`.
</Reveal>

## Measure Every Element Against the Last

A common job over a sequence is to compare every element against one fixed element, and the last element is the fixed one here. You read both tabs and name what genuinely changes and what stays fixed.

Study the two programs below. Each prints the last element of the same four-value sequence, then walks the whole sequence and prints how far each element sits below that last one, computed as the last element minus the current element. Before opening the reveal, write down the five lines you expect each program to print, then name one thing that is truly different between the languages and one thing that is the same.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="last.py"
nums = [5, 8, 2, 6]
print(nums[-1])
for x in nums:
    print(nums[-1] - x)
```
</TabItem>
<TabItem label="Rust">
```rust title="last.rs"
fn main() {
    let nums = vec![5, 8, 2, 6];
    println!("{}", nums[nums.len() - 1]);
    for x in &nums {
        println!("{}", nums[nums.len() - 1] - x);
    }
}
```
</TabItem>
</Tabs>

<Reveal label="Reveal the outputs and what differs">
```bash title="Run the Python program"
python3 last.py
```

```text frame="terminal" title="Output"
6
1
-2
4
0
```

```bash title="Compile and run the Rust program"
rustc last.rs
./last
```

```text frame="terminal" title="Output"
6
1
-2
4
0
```

The last element is `6`. The loop then prints `6 - 5` which is `1`, `6 - 8` which is `-2`, `6 - 2` which is `4`, and `6 - 6` which is `0`. The second element sits above the last, so its distance is negative, which is the kind of result worth predicting rather than assuming.

<WhatDiffers>
<Fragment slot="differs">
Python reaches the last element with a negative index, `nums[-1]`, which counts one back from the end, and it does so inside the loop on every pass. Rust has no negative index, so each pass computes the last position by hand as `nums[nums.len() - 1]`, one less than the length. Iterating differs too: Python writes `for x in nums`, while Rust writes `for x in &nums`, the leading `&` letting the loop read the elements without taking the vector away, so `nums` stays usable, which matters here because the body reaches back into `nums` on every pass. What stays fixed is that both index from zero, both treat `6` as the last element, and both print the same five lines in the same order.
</Fragment>
</WhatDiffers>
</Reveal>

## Complete the Adjacent-Sums Loop

One line of the program below is unfinished: the loop line itself. The finished program walks `[10, 20, 30]` and prints the sum of each element and the one after it, exactly two lines, `30` then `50`, and exits cleanly. You choose the bound that makes it do that, and commit to what the other two candidates would do.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="bounds.py (one bound missing)"
nums = [10, 20, 30]
for i in range(____):  # the missing bound
    print(nums[i] + nums[i + 1])
```
</TabItem>
<TabItem label="Rust">
```rust title="bounds.rs (one range missing)"
fn main() {
    let nums = vec![10, 20, 30];
    for i in ____ {  // the missing range
        println!("{}", nums[i] + nums[i + 1]);
    }
}
```
</TabItem>
</Tabs>

The candidates for the blank:

- **A.** `len(nums)` in Python, `0..nums.len()` in Rust.
- **B.** `len(nums) - 1` in Python, `0..nums.len() - 1` in Rust.
- **C.** `len(nums) - 2` in Python, `0..nums.len() - 2` in Rust.

Commit to one, and write down exactly what the program prints or does with each of the other two, before opening the reveal.

<Reveal label="Reveal the completing bound and what the other candidates do">
**B completes the program.** With `range(len(nums) - 1)`, or `0..nums.len() - 1`, the loop runs `i` over `0` and `1`: the first pass prints `nums[0] + nums[1]`, which is `10 + 20 = 30`, and the second prints `nums[1] + nums[2]`, which is `20 + 30 = 50`. Because the body reads `nums[i + 1]`, one position ahead of `i`, the loop must stop at the second-to-last element so that `i + 1` still names a real element on the final pass.

```bash title="Run the completed Python program"
python3 bounds.py
```

```text frame="terminal" title="Output"
30
50
```

Rust prints the same two lines.

**A runs one pass too many.** `range(len(nums))` lets `i` reach `2`, and that pass reads `nums[2] + nums[3]`; position `3` does not exist in a three-element list, so both languages stop the program right after the two correct sums:

```bash title="Run it with candidate A"
python3 bounds.py
```

```text frame="terminal" title="Output"
30
50
Traceback (most recent call last):
  File "bounds.py", line 3, in <module>
    print(nums[i] + nums[i + 1])
                    ~~~~^^^^^^^
IndexError: list index out of range
```

```bash title="Compile and run the Rust version with candidate A"
rustc bounds.rs
./bounds
```

```text frame="terminal" title="Output"
30
50
thread 'main' panicked at bounds.rs:4:38:
index out of bounds: the len is 3 but the index is 3
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

**C stops one pass too soon.** `range(len(nums) - 2)` runs `i` over `0` only, so the program prints `30`, skips the `20 + 30` pair entirely, and exits with no error at all:

```bash title="Run it with candidate C"
python3 bounds.py
```

```text frame="terminal" title="Output"
30
```

C is the quieter mistake of the two: nothing crashes, and only holding the output against the two lines the task promises reveals the missing sum. A loop that reads one element ahead must run exactly one position short of the length. Shorter than that loses pairs, longer than that reads past the end, and only one of those failures announces itself.
</Reveal>

## Write the Reading Total

Write a program that builds the list of readings `[3, 1, 4, 1, 5]`, adds them up with a loop, and prints the total.

<Reveal label="Reveal a sample solution">
This is a sample solution; a correct program that reaches the same total can look different from this one.

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="readings.py"
readings = [3, 1, 4, 1, 5]
total = 0
for x in readings:
    total = total + x
print(total)
```
</TabItem>
<TabItem label="Rust">
```rust title="readings.rs"
fn main() {
    let readings = vec![3, 1, 4, 1, 5];
    let mut total = 0;
    for x in &readings {
        total = total + x;
    }
    println!("{}", total);
}
```
</TabItem>
</Tabs>

```bash title="Run the Python program"
python3 readings.py
```

```text frame="terminal" title="Output"
14
```

```bash title="Compile and run the Rust program"
rustc readings.rs
./readings
```

```text frame="terminal" title="Output"
14
```
</Reveal>

## Bridge

These three reps feed the recitation family that encodes, decodes, or cleans a sequence one element at a time, walking a string or a list from front to back and building a new sequence as it goes. Growing a list with a push, reaching its elements by a valid index, and catching the off-by-one that reads past the end are the exact moves that family runs on longer sequences, and the hand-tracing you just practiced is the guided first rung of that ladder.
