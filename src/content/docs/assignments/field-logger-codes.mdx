WRO's field air-quality network transmits over a satellite or LoRa radio link at stations with no grid connection, and every byte a station sends costs battery power it may not get back until the next sunny day. To keep each report small, a station packs its air-quality reading into a compact three-character code instead of sending the whole number as plain text. Your job as a junior engineer on the office's software team is to write the piece of the pipeline that builds that code from a reading, and the small piece that turns one of its characters back into the value it stands for.

## How This Assignment Works

The problem is solvable in Python or Rust, whichever you prefer. The program's `main`, its console input and output, and the local test runner are already written; you write the two functions named below, and the automated grader calls each directly with values it chooses, reading only what you `return`. ## The Problem

The [Sensor Drift Check](/assignments/sensor-drift-check/) assignment defined the field archive's reading line: one line per reading, three fields in a fixed order, `station_id,code,reference_ugm3`. `station_id` is always exactly six characters, and `code` is always exactly three base-36 characters: the reading's whole number of micrograms per cubic meter, already rounded to the nearest unit before it ever reaches your function. You are building the piece of the pipeline that produces `code`, and the small primitive a later step will need to read one of its characters back.

A base-36 digit is a single character that can stand for more values than an ordinary decimal digit. The ten characters `0` through `9` stand for the values zero through nine, exactly like a normal digit, and the lowercase letters `a` through `z` continue counting from there: `a` stands for ten, `b` for eleven, and so on up through `z`, which stands for thirty-five. Three of these characters in a row can therefore hold any whole number from `0` up to `zzz`, far more than three decimal digits could hold in the same three characters.

Each station's radio draws its transmissions from a small solar-charged battery that holds enough charge for about 40 transmissions before it needs a full day of sun to recover.

Write two functions:

1. `code_for(reading_ugm3)` must return the reading's three-character base-36 code, most significant character first, so the code's leftmost character carries the largest share of the reading's value and its rightmost character the smallest.
2. `digit_value(c)` must return the value a single base-36 digit character stands for: `0` through `9` for the characters `'0'` through `'9'`, and `10` through `35` for the lowercase letters `'a'` through `'z'`. Any other character, including an uppercase letter, must return `-1`.

`code_for` and `digit_value` are two halves of one codec, not a matched pair to test against each other. `code_for` builds a whole three-character code in a single call; `digit_value` only ever looks at one character at a time. Turning a code you built back into the number it represents is a job for a later step in the pipeline, not something this assignment asks you to write or test.

<WhatDiffers>
<Fragment slot="differs">
Python has no separate character type: `ord(c)` gives a character's code and `chr(n)` turns a code back into a one-character string. Rust's `char` is its own type; you get a character's code with `c as u32`, and to turn a code back into a character you cast the byte-sized value with `as u8` first, then `as char`.
</Fragment>

## Paper Practice

Trace this program by hand, on paper. It uses the same character-to-number arithmetic your two functions above are built from, applied to a short run of individual characters rather than a fixed-width code. Build a variable table with a row for each call to `digit_or_flag`, tracking the character passed in, the value returned, and `total` after each call. Write the exact value the program prints.

```python title="trace_me.py"
def digit_or_flag(c):
    if c >= '0' and c <= '9':
        return ord(c) - ord('0')
    else:
        return -1

total = 0
total = total + digit_or_flag('7')
total = total + digit_or_flag('#')
total = total + digit_or_flag('2')
print(total)
```

<Reveal label="Reveal the completed trace">
Each call checks whether its character is one of the ten digit characters. `'7'` and `'2'` are; `'#'` is punctuation, not a digit character, so it falls through to the `-1` sentinel.

| Call | `c` | returns | `total` after |
|---|---|---|---|
| `digit_or_flag('7')` | `'7'` | `7` | `7` |
| `digit_or_flag('#')` | `'#'` | `-1` | `6` |
| `digit_or_flag('2')` | `'2'` | `2` | `8` |

The program prints `8`. The same program written in Rust prints the same whole number, `8`, since every value here is a whole `i32`, never a float.
</Reveal>
