The Willamette Resource Office coordinates prescribed burns for oak savanna and prairie restoration across the valley. ## The Problem

Each morning before a burn, the crew logs four numbers at the unit: the wind speed, the relative humidity, the fuel moisture, and a visibility index for that day's regional air-quality report.

WRO's field app condenses the day into a single status code: `0` when the unit is cleared to burn, `1` when conditions are marginal, `2` when conditions are unsafe, and `3` when a county burn ban is in effect. Three live readings feed the decision, the wind speed, the relative humidity, and the fuel moisture, but the burn ban outranks all three.

Write `burn_clearance_status(wind_speed_mph, relative_humidity_percent, fuel_moisture_percent, burn_ban_declared)`, returning the status code. What it must return, in this priority order:

1. Return `3` whenever `burn_ban_declared` is `true`. A county burn ban outranks every other check.
2. Otherwise, return `2` when the wind speed is above `20.0` miles per hour, or the relative humidity is below `25.0` percent, or the fuel moisture is below `10.0` percent.
3. Otherwise, return `1` when the three readings are not all inside the ideal window: the wind speed at or below `12.0` miles per hour, the relative humidity at or above `40.0` percent, and the fuel moisture at or above `15.0` percent, all three at once.
4. Otherwise, return `0`.

The function returns a whole-number status code (`0`, `1`, `2`, or `3`). How you arrange the comparisons, which of `and`, `or`, and `not` each outcome needs, and what intermediate values you give names to along the way, is entirely your decision.

**Assumptions and edge cases.** All four readings come from the site's automated weather station and fuel moisture probe, except `burn_ban_declared`, which the county fire marshal's office sets by mid-morning. The three numeric windows above are WRO's own operating prescription for this burn type, not a published statewide standard; real agency prescriptions vary by fuel type, unit, and region. The boundaries are exact: `20.0` miles per hour, `25.0` percent, and `10.0` percent are the safety thresholds, and a reading sitting exactly at one of them does not breach it. The ideal window needs `12.0`, `40.0`, and `15.0` exactly met, so a day sitting exactly on a safety threshold is marginal, not unsafe and not cleared. A declared burn ban always returns `3`, even when all three readings would otherwise be inside the ideal window.

## Paper Practice

Trace this program by hand, on paper. It uses nested function calls and a boolean condition, the patterns from the [Scope and the Call Stack](/lectures/scope-and-the-call-stack/) and [Booleans and Conditionals](/lectures/booleans-and-conditionals/) lectures. Build a variable table: for the call to `is_dry_fuel`, write the value its `fuel_moisture_percent` parameter holds and what it returns; then, for `check_burn_readiness`, write the values bound to its two parameters, to `dry_fuel`, and to `result`. Write the exact value the program prints.

```python title="trace_me.py"
def is_dry_fuel(fuel_moisture_percent):
    return fuel_moisture_percent < 10

def check_burn_readiness(wind_speed_mph, fuel_moisture_percent):
    dry_fuel = is_dry_fuel(fuel_moisture_percent)
    if wind_speed_mph <= 12 and not dry_fuel:
        result = 1
    else:
        result = 0
    return result

status = check_burn_readiness(9, 14)
print(status)
```

<Reveal label="Reveal the completed trace">
The call `check_burn_readiness(9, 14)` pushes a frame with `wind_speed_mph = 9` and `fuel_moisture_percent = 14`. Inside it, `is_dry_fuel(14)` pushes a second frame with `fuel_moisture_percent = 14`, computes `14 < 10`, and returns `False`; that frame is popped, and `False` is bound to `dry_fuel` in `check_burn_readiness`'s own frame.

| Line | frame | `wind_speed_mph` | `fuel_moisture_percent` | `dry_fuel` | `result` |
|---|---|---|---|---|---|
| `is_dry_fuel(14)` called | `is_dry_fuel` | | `14` | | |
| `return fuel_moisture_percent < 10` | `is_dry_fuel` | | `14` | | (returns `False`) |
| `dry_fuel = is_dry_fuel(fuel_moisture_percent)` | `check_burn_readiness` | `9` | `14` | `False` | |
| `if wind_speed_mph <= 12 and not dry_fuel:` | `check_burn_readiness` | `9` | `14` | `False` | |
| `result = 1` | `check_burn_readiness` | `9` | `14` | `False` | `1` |

The condition checks `9 <= 12`, which is `True`, `and`ed with `not dry_fuel`, which is `not False`, or `True`. `True and True` is `True`, so the `if` block runs, binding `result` to `1`. The program prints `1`.
</Reveal>
