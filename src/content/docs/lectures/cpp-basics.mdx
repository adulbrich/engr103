This page is an appendix, not a lecture. Nothing on it is examinable, no other page depends on it, and you do not need to read it to finish this course. It exists for one moment: the day you enroll in a course taught in C++ and want to carry what you already know across. Every construct this course taught you in Python and Rust exists in C++ under a third spelling, and this page maps them one by one, so your first week of C++ feels like a translation exercise rather than a new language. Rust borrowed much of its surface spelling from C++, so if you have been reading the Rust tabs all term, most of what follows will look half familiar already.

## Hello, World and the Compile-and-Run Loop

You know this program as `print("Hello, world!")` in Python and as a `fn main` holding a `println!` in Rust. In C++ it looks like this, in a file named `hello.cpp`:

```cpp title="hello.cpp"
#include <iostream>

int main() {
    std::cout << "Hello, world!" << std::endl;
    return 0;
}
```

C++ is a compiled language, so the loop you know from Rust applies unchanged: compile the file into an executable, then run the executable, and recompile after every edit because the executable does not update itself. The compiler is `g++`, and its command plays the role `rustc hello.rs` played:

```bash title="Compile, then run"
g++ -o hello hello.cpp
./hello
```

```text frame="terminal" title="Output"
Hello, world!
```

The `-o hello` names the executable; without it you get a file with the default name `a.out`. Behind that one command, `g++` actually runs three steps in a row, and knowing their names helps you read its error messages. First comes **preprocessing**, which handles every line that starts with `#`. The line `#include <iostream>` is an instruction to this step: it pastes the text of the `iostream` header into your file before the compiler ever sees your code, so that the compiler knows what `std::cout` is. Second comes **compilation**, which translates the preprocessed source into machine code. Third comes **linking**, which joins your compiled code with the compiled code of the standard library into one executable.

So `#include` is a text-paste that happens before compilation, not a library being added at the end. If you delete that line, the compile step fails with "use of undeclared identifier 'std'", because the paste that would have declared `std::cout` never happened. This is the C++ answer to a problem Rust solved with `use std::collections::HashMap;`: both lines bring a name into view before you use it, but Rust's is a language feature the compiler understands, while C++'s is a literal text substitution done by the preprocessor.

Reading the program itself: `int main() { ... }` is the entry point, the same job as Rust's `fn main`, except the return type `int` is written in front of the name and `return 0;` hands the operating system a code meaning "finished successfully". `std::cout` is the terminal's output stream, `<<` pushes a value into it, `std::endl` ends the line, and the `;` ends the statement, exactly as it does in Rust.

## Types and Variable Declarations

You know a variable as a name for a value in memory: Python creates one with a bare `name = value` and lets the name carry no type, while Rust writes `let count: i32 = 10;` and fixes the type for good. C++ is closest to Rust, but it puts the type first and drops the keyword: the type, then the name, then the value.

```cpp title="types.cpp"
#include <iostream>
#include <string>

int main() {
    int count = 10;
    double price = 2.5;
    bool door_open = true;
    std::string name = "Ada";
    count = count + 1;
    std::cout << count << std::endl;
    std::cout << price << std::endl;
    std::cout << door_open << std::endl;
    std::cout << name << std::endl;
    return 0;
}
```

```text frame="terminal" title="Output"
11
2.5
1
Ada
```

The four types map directly onto what you know: `int` is Rust's `i32`, a fixed-size whole number, not Python's grow-forever integer; `double` is Rust's `f64`; `bool` holds `true` or `false`, spelled lowercase as in Rust, and notice that `std::cout` prints a `bool` as `1` or `0` unless you ask otherwise; `std::string` is the growable text type, Rust's `String`, and it needs `#include <string>` the way `HashMap` needed its `use` line.

Two differences from Rust hide inside this familiar picture, and both matter. First, every C++ variable is mutable by default: the `count = count + 1;` above needs no `mut`, and if you want a name that cannot be reassigned you must add a keyword, `const int limit = 100;`. Rust's default and C++'s default are exact opposites. Second, and dangerously, a C++ variable is uninitialized by default. Writing a declaration without a value compiles, and so does reading from it:

```cpp title="An uninitialized read (compiles, undefined behavior)"
int count;                        // count exists, but holds whatever bytes happened to be there
std::cout << count << std::endl;  // compiles and runs: prints garbage, not an error
```

Python cannot express this mistake, because a name does not exist until you assign to it. Rust catches it before the program runs: the compiler refuses to build a read of a variable that might not have a value. C++ accepts it silently, and what the program then prints is whatever bytes were left in that spot of memory. The working rule is simple: give every variable a value on the line that declares it.

## Functions

You know a typed function signature from Rust: `fn area(width: f64, height: f64) -> f64`. C++ carries exactly the same information, rearranged so the return type leads, the way `int` led `main` above. Each parameter is written type-first too, like a small declaration.

```cpp title="area.cpp"
#include <iostream>

double area(double width, double height) {
    return width * height;
}

int main() {
    std::cout << area(3.0, 4.5) << std::endl;
    return 0;
}
```

```text frame="terminal" title="Output"
13.5
```

Read `double area(double width, double height)` as "a function named `area` that takes two `double`s and returns a `double`", which is precisely what the Rust signature said with its arrow. Python's `def area(width, height):` names the same function with the types left unstated. Everything else you know transfers: arguments are copied into parameters, the parameters are local to the function, and calling it looks identical in all three languages. One small habit does not transfer: Rust let you end a function with a bare expression and no `return`. C++ does not; a function that promises a value must say `return` explicitly. A function that returns nothing declares the return type `void`, C++'s spelling for what Python left silent and Rust wrote as no arrow at all.

## Choosing a Path: if and else if

You know branching as `if`/`elif`/`else` in Python and `if`/`else if`/`else` in Rust. C++ uses Rust's spelling with one visible change: the condition must sit inside parentheses.

```cpp title="grade.cpp"
#include <iostream>

int main() {
    int score = 78;
    if (score >= 90) {
        std::cout << "excellent" << std::endl;
    } else if (score >= 70) {
        std::cout << "good" << std::endl;
    } else {
        std::cout << "keep going" << std::endl;
    }
    return 0;
}
```

```text frame="terminal" title="Output"
good
```

The chain works exactly as you learned: conditions are tested from the top, the first true one wins, and at most one branch runs. The operators inside the conditions are Rust's, symbol for symbol: `==`, `!=`, `<`, `<=`, `>`, `>=` for comparison, and `&&`, `||`, `!` for and, or, and not, where Python spelled those three as words. Short-circuit evaluation works the same way it did in both course languages.

## Loops: while and the Three-Part for

You know a `while` loop that repeats as long as a condition holds, and a counted loop that visits `0, 1, 2` in turn, written `for i in range(3)` in Python and `for i in 0..3` in Rust. The C++ `while` is the one you already know, parentheses around the condition and nothing else new. The counted loop is where C++ looks different: it uses a three-part `for` header that spells out by hand what `range` and `0..3` did for you.

```python title="A counted loop (Python)"
for i in range(3):
    print("pass", i)
```

```rust title="A counted loop (Rust)"
for i in 0..3 {
    println!("pass {}", i);
}
```

```cpp title="loops.cpp"
#include <iostream>

int main() {
    int countdown = 3;
    while (countdown > 0) {
        std::cout << countdown << std::endl;
        countdown = countdown - 1;
    }
    for (int i = 0; i < 3; i++) {
        std::cout << "pass " << i << std::endl;
    }
    return 0;
}
```

```text frame="terminal" title="Output"
3
2
1
pass 0
pass 1
pass 2
```

Read the header `for (int i = 0; i < 3; i++)` as three fields separated by semicolons. The first, `int i = 0`, declares the loop variable and runs once, before anything else. The second, `i < 3`, is the condition, checked before every pass exactly like a `while` condition; the loop ends the moment it is false. The third, `i++`, runs after each pass and means `i = i + 1`; C++ programs also write `i += 1`, the same `+=` shorthand Python and Rust accept. So the header is nothing new, only exploded: it is the initialize-check-step machinery that `range(3)` and `0..3` bundled up, laid out in the open where you can change any part of it. `break` and `continue` exist in C++ and mean what they meant in both course languages.

## A Growable List: std::vector

You know this collection as a list in Python and a `Vec` in Rust: an ordered, growable sequence indexed from zero. C++ calls it `std::vector`, and like Rust's `Vec` it commits to one element type, written in angle brackets. It needs `#include <vector>`.

```cpp title="readings.cpp"
#include <iostream>
#include <vector>

int main() {
    std::vector<int> readings;
    readings.push_back(10);
    readings.push_back(20);
    readings.push_back(30);
    std::cout << readings[1] << std::endl;
    std::cout << readings.size() << std::endl;
    int total = 0;
    for (int r : readings) {
        total = total + r;
    }
    std::cout << total << std::endl;
    return 0;
}
```

```text frame="terminal" title="Output"
20
3
60
```

The mapping is one to one. Appending is `push_back`, where Python said `append` and Rust said `push`. Length is `.size()`, where Python said `len(readings)` and Rust said `.len()`. Indexing is the same square brackets, `readings[1]`, counting from zero. Walking the elements is `for (int r : readings)`, the shape of Python's `for r in readings` and Rust's `for r in &readings`.

One of those familiar spellings hides the sharpest trap on this page: `readings[i]` performs no bounds checking at all. Python answers an index past the end with an `IndexError`, and Rust stops the program with a panic that names the bad index. C++ does neither; an out-of-bounds `[]` compiles and then reads whatever memory sits past the end of the vector, which is undefined behavior, not an error. The What Will Surprise You section below shows what that looks like. When you want a checked lookup, C++ has one, `readings.at(1)`, which stops the program with an `std::out_of_range` error on a bad index; the unchecked `[]` is simply what most C++ code writes, so you must bring the caution yourself.

## Console Output and Input

You know printing as `print(...)` and `println!("{}", ...)`, and reading as Python's `input(...)` followed by `int(...)`, or Rust's `read_line` followed by `parse`. C++ handles both directions with streams: `std::cout` and `<<` push values out, and `std::cin` with the arrows reversed, `>>`, pulls values in.

```cpp title="greet.cpp"
#include <iostream>
#include <string>

int main() {
    std::string name;
    int age;
    std::cout << "Name: ";
    std::cin >> name;
    std::cout << "Age: ";
    std::cin >> age;
    std::cout << "Hello " << name << ", next year you will be " << age + 1 << std::endl;
    return 0;
}
```

```text frame="terminal" title="One run of the program"
Name: Ada
Age: 36
Hello Ada, next year you will be 37
```

Two things transfer directly and one is genuinely new. Output chains: `std::cout << "Hello " << name` prints the pieces in order, the same job as one `print` with several arguments, and nothing is printed on a new line unless you send `std::endl` or `"\n"`. Prompting works as it did in both languages: print the question, then read the answer. The new part is that `std::cin >> age` parses for you: because `age` was declared as an `int`, the stream reads the next whitespace-separated word of input and converts it to an integer in one step, with no separate `int(...)` or `.parse()` call. The declared type of the variable is the instruction. That convenience has a cost you already learned to fear in the validation lecture: if the user types something that is not a number, `std::cin` does not stop the program; it silently fails, sets the number to zero, and refuses every further read until the error is cleared, so real C++ programs must check the stream's state after reading, just as your Python needed `try` and your Rust needed to `match` the `Result`.

## What Will Surprise You

The deepest surprise is not a spelling but a temperament. C++ compiles ahead of time like Rust, with types checked and a whole executable produced, so it is tempting to assume the compiler catches what Rust's caught. It does not. The three mistakes this course watched Rust refuse to compile, reading an uninitialized variable, indexing past the end of a collection, and keeping a reference to a value that no longer exists, all compile in C++ without complaint. They are **undefined behavior**: the language makes no promise at all about what the running program then does. Here is the out-of-bounds read from the vector section, made real:

```cpp title="Reading past the end (compiles, undefined behavior)"
#include <iostream>
#include <vector>

int main() {
    std::vector<int> readings;
    readings.push_back(10);
    readings.push_back(20);
    std::cout << readings[5] << std::endl;  // index 5 of 2 elements: compiles anyway
    return 0;
}
```

```text frame="terminal" title="What one run printed (could be anything)"
0
```

That `0` is not an answer; it is whatever bytes sat in memory past the vector's end on that particular run. Another run, another machine, or another compiler could print a different number, crash, or corrupt data elsewhere in the program while appearing to work. The same is true of the uninitialized `count` earlier, which printed `-121782184` when this page's examples were run, and of a dangling reference, a reference returned to or kept from a value whose lifetime has ended, which the borrow checker made impossible in Rust and which C++ will compile without a word. This is why the memory-model lectures matter more in C++, not less: there is no garbage collector cleaning up behind you as in Python, and no borrow checker refusing the unsafe program as in Rust. The pictures you drew of names, values, and lifetimes are the only safety net that travels with you.

The smaller surprises are quick to list. Integer division truncates as it did in Rust: `7 / 2` is `3`, and you need `7.0 / 2.0` to get `3.5`, so Python's always-a-float `/` is the odd one out among the three languages. Semicolons end nearly every statement and braces wrap every block, exactly as in Rust, so Python's indentation-as-structure does not carry over. And each capability you use needs its header pasted in at the top, `#include <iostream>` for streams, `<string>` for strings, `<vector>` for vectors; forgetting one earns a compile error about an undeclared name, which is the preprocessor story from the first section showing up in practice. None of this changes what a loop is, what a function is, or what a boundary case is. Those you already own, and they are the reason this page can be short.
