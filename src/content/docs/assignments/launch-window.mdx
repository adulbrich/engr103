### Problem 3: Break-Even on the Supply Runs

**Context.** The station begins the mission with a fixed mass deficit it must make up. Each automated supply run delivers a fixed amount of usable mass but also spends some mass to launch, so each run nets the difference between the two. You need the number of complete runs required to erase the deficit.

**Requirements.**

1. In the provided program, set `net_per_run` to the mass a single run adds after its own launch cost: the delivered mass `delivered_kg` minus the launch cost `cost_kg`.
2. Set `runs` to the smallest whole number of runs whose combined net mass reaches the deficit `deficit_kg`. A partial run is not possible, so round the number of runs up to the next whole number.

This is a break-even calculation: you are solving for the number of equal net steps that first covers a fixed target. The modeling step is seeing "erase a fixed deficit with equal net steps, rounding up" as that break-even count; the analysis step is computing the net per run and the rounded-up count with the variables and integer division from the [Variables and State](/lectures/variables-and-state/) lecture.

**The program.**


<Aside type="tip" title="Rounding up without a fraction">
You have not met a rounding function or an `if` statement yet, but there is an arithmetic way to get the smallest whole number of equal steps that reaches a target. For positive whole numbers, `(target + step - 1) // step` gives exactly that count: it lands on the next whole number whenever the plain division would have left a remainder, and lands exactly when the target divides evenly. Here the target is the deficit and the step is the net per run. Decide for yourself which value is the target and which is the step.
</Aside>

**Assumptions and edge cases.** `delivered_kg` is greater than `cost_kg`, so `net_per_run` is a positive whole number, and `deficit_kg` is a positive whole number. If the starter later changes these three values, your two lines must still be correct, so compute `runs` from the named values, never hard-code `7`.
