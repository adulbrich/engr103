## Problem Set

### Problem 1: The Countdown

**Context.** The launch sequence is `500` seconds long. The console shows it as whole minutes and the seconds left over, not as one large number.

**Requirements.**

1. In the provided program, set `minutes` to the number of whole minutes in `total_seconds`, and `seconds` to the seconds left over after those whole minutes. There are `60` seconds in a minute. Use integer division for the whole minutes and the remainder operator for the leftover seconds.

The modeling step is choosing to show the countdown as a (minutes, seconds) pair; the analysis step is computing each with the operators from the [Expressions and Operators](/lectures/expressions-and-operators/) lecture.

**The program.**

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="countdown.py (provided)"
total_seconds = 500
# TODO: replace each 0 with the right computation.
minutes = 0    # whole minutes in total_seconds
seconds = 0    # leftover seconds after the whole minutes
print(minutes)
print(seconds)
```
</TabItem>
<TabItem label="Rust">
```rust title="countdown.rs (provided)"
fn main() {
    let total_seconds = 500;
    // TODO: replace each 0 with the right computation.
    let minutes = 0;   // whole minutes in total_seconds
    let seconds = 0;   // leftover seconds after the whole minutes
    println!("{}", minutes);
    println!("{}", seconds);
}
```
</TabItem>
</Tabs>

**Expected output.**

```text frame="terminal" title="Output"
8
20
```

**Assumptions and edge cases.** `total_seconds` is a whole number, zero or greater. Your two lines must work by the same rule if the starter later changes `total_seconds` to another value, so compute from `total_seconds`, never hard-code `8` and `20`.

<WhatDiffers>
<Fragment slot="differs">
Python writes integer division as `//` and Rust writes it as `/` between two whole numbers; both discard the fraction. The remainder operator is `%` in both. The two printed numbers are the same in each language.
</Fragment>
</WhatDiffers>

### Problem 2: The Fuel Margin, and One of HAB's Suggestions

**Context.** The burn needs its base propellant plus a safety margin on top. The base load is `1000` kilograms and the margin is `15` percent, so the fueled mass should be `1150` kilograms.

**Requirements.**

1. In the provided program, set `fueled_kg` to the base mass plus `margin_percent` percent of the base mass. All three values are whole numbers, so use integer arithmetic. For a base of `1000` and a margin of `15`, the result is `1150`.

The modeling step is writing "add a fifteen percent margin" as an arithmetic expression; the analysis step is computing it and checking HAB's version against your own.

**The program.**

<Tabs syncKey="lang">
<TabItem label="Python">
```python title="fuel.py (provided)"
base_kg = 1000
margin_percent = 15
# TODO: replace the 0 with the fueled mass, base plus the margin.
fueled_kg = 0
print(fueled_kg)
```
</TabItem>
<TabItem label="Rust">
```rust title="fuel.rs (provided)"
fn main() {
    let base_kg = 1000;
    let margin_percent = 15;
    // TODO: replace the 0 with the fueled mass, base plus the margin.
    let fueled_kg = 0;
    println!("{}", fueled_kg);
}
```
</TabItem>
</Tabs>

**Expected output.**

```text frame="terminal" title="Output"
1150
```

<Aside type="danger" title="HAB suggested this line. Check it before you use it.">
HAB offered `base_kg * (1 + margin_percent // 100)` for the fueled mass (in Rust, `base_kg * (1 + margin_percent / 100)`). Work out what it prints before you trust it.

For a base of `1000` and a margin of `15`, HAB's line prints `1000`, not `1150`: the margin vanishes. The reason is integer division. `margin_percent // 100` is `15 // 100`, which is `0`, because integer division throws away the fraction, so HAB's `1 + 0` multiplies the base by `1` and adds no margin at all. Write the margin so the integer division does not erase it: add the base's fifteen percent to the base, rather than folding a fraction under `100` into a whole-number factor.
</Aside>

**Assumptions and edge cases.** `base_kg`, `margin_percent`, and the result are whole numbers. A margin of `0` must leave the base mass unchanged.
