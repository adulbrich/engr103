This ladder lists, week by week, the Python and Rust constructs the course has introduced by that point. It grows cumulatively: a construct introduced in an earlier week stays introduced in every later week.

For you as a student, the ladder is a **recommendation, not a rule**. It is the set of tools you are guaranteed to have seen, so it is a safe vocabulary to reach for when you are not sure what you are allowed to use. But if you already know a feature that appears further along, or one the course never covers, you are free to use it: nothing here forbids you from writing code you understand. Recitations and exams assess your understanding, not your restraint.

What the ladder does guarantee runs the other way. **Every graded assessment is solvable using only the constructs listed for its week.** An assignment, recitation, or exam will never require a feature you have not been taught yet, so a student who has followed the course can always solve it with the tools already in hand. The right-hand column below names what has not been introduced yet, so you can see at a glance what a given week's work will never depend on.

## The weekly ladder

| Week | Newly introduced in Python | Newly introduced in Rust | Not yet introduced |
|---|---|---|---|
| 1 | `print`; int, float, bool, str literals; arithmetic operators (`+ - * /`) and precedence; integer division `//` and flooring; `%`; implicit coercion | `println!` with `{}` placeholders and the `fn main` wrapper; `i32`, `f64`, `bool`, `&str`; arithmetic and precedence; integer division and truncation; `%` | variables, functions, conditionals, loops |
| 2 | binary literals; variables and assignment; `UPPER_CASE` constants; `input`; `int()`/`float()` parsing | binary literals; `let`, `let mut`, shadowing; `const`; `read_i32`/`read_f64` (provided) | functions, conditionals, loops |
| 3 | `def` functions with parameters and return | `fn` functions with typed params and return; calling functions | conditionals, loops |
| 4 | local and function scope; comparisons; `and`, `or`, `not`; `if`/`else` | scope, nested `{ }` blocks, the call stack; comparisons; `&&`, `\|\|`, `!`; `if`/`else` | `elif`/`else if` chains, loops, collections |
| 5 | `elif` chains; `try`/`except`; comparing floats with a tolerance | `else if` chains; `match`; `.parse()`; `Result`; comparing floats with a tolerance | loops, collections |
| 6 | `assert`; test functions | `assert!`; test functions | loops, collections |
| 7 | `while`; `for` over `range`; `break`/`continue`; nested loops | `while`; `for` over ranges; `break`/`continue`; nested loops | collections |
| 8 | strings (indexing, slicing, searching, building); characters; `list`; indexing; `len`; iteration; `append` | `String`/`&str` method subset; `char`; `Vec`; indexing; `.len()`; iteration; `push` | the memory model, references, dictionaries |
| 9 | aliasing (two names, one list); passing lists to functions | `&`/`&mut` references; moves; borrowing-lite; passing `Vec` to functions | dictionaries and maps |
| 10 | `dict` (advanced extra) | `HashMap` (advanced extra) | nothing new required |

## Not used in this course

The course never teaches these constructs, so no lecture, activity, or assessment relies on them, and no graded problem will ever require one. You are still free to use any you already know; they simply are not part of what the course expects.

- **Python:** comprehensions, lambdas, and f-string format specs beyond the basics.
- **Rust:** writing your own generic code (defining type parameters, traits, lifetimes), and borrowing before week 9. `parse::<T>` is taught in week 5 as a fixed spelling you use as written, so using it is not writing generic code.
